Understanding the Virtual DOM

Core Concept schedule 15 min read

At the heart of React's performance lies the Virtual DOM. Unlike directly manipulating the browser's DOM—which is slow and computationally expensive—React creates a lightweight copy in memory.

When the state of a component changes, React updates the virtual DOM first. It then compares this updated version with the previous version of the virtual DOM. This process is called "diffing".

Figure 1.1: Visualizing the diffing algorithm process

Why is it faster?

The browser is slow at layout recalculations. By batching updates and only changing the specific nodes that are different, React minimizes the number of reflows and repaints the browser has to perform.

Counter.jsx 
function Counter() {
  const [count, setCount] = useState(0);

  // Only the span text updates in the real DOM
  return (
    <div>
      <p>You clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>
        Click me
      </button>
    </div>
  );
}
